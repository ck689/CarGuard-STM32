OVERVIEW

三个版本在做什么？一句话看懂

想象你在造一辆"智能小车"的仪表盘。V0是你刚学会用"对讲机"（串口）喊口令控制车灯和喇叭；V1是你装上了"电压表"和"温度计"（ADC），能读数据了但只能在电脑上看；V2是你终于把屏幕（OLED）装在车上，脱离电脑也能看到数据。

新增：USART串口、LED、BEEP

CHAPTER · V0

V0：工程骨架 + 串口通信（用指令控制LED和蜂鸣器）

V0 目标功能：在电脑串口助手里输入 LED1_ON，板子上的LED就亮；输入 BEEP_ON，蜂鸣器就响。这是整个项目的"地基"——把工程跑通、把串口通信用熟。

1. 硬件连接（就3个东西）

图2：V0 硬件连接图
注意：串口是交叉连接——模块的TX接单片机的RX(PA10)，模块的RX接单片机的TX(PA9)。接反了收不到数据。

2. 代码运行流程（先看全局，再看细节）

图3：V0 程序运行流程图
核心思想：中断负责"收"，主循环负责"处理"。中断像快递员把信件塞进信箱（RxBuf），主循环像你时不时去看信箱有没有信（RxFlag），有信就拆开处理。两者互不阻塞。

3. 核心代码逐行拆解

① 初始化部分（main函数开头，只执行一次）

文件：user/main.c — 初始化段
int main(void) { // ===== 初始化（只执行一次）===== LED_Init(); // ① 配置PA8为推挽输出，LED引脚准备好 BEEP_Init(); // ② 配置PB0为推挽输出，蜂鸣器引脚准备好 USART1_Init(115200); // ③ 配置串口波特率115200，使能接收中断 printf("CarGuard V0 启动成功！\r\n"); // ④ 串口打印欢迎语（证明启动成功）
通俗理解：初始化就像开店前的准备——先把灯装好（LED_Init）、把喇叭装好（BEEP_Init）、把对讲机调好频率（USART1_Init），然后对着对讲机喊一声"我开张了"（printf）。这些事只做一次。

② 主循环：检查有没有新指令

文件：user/main.c — 主循环判断
while (1) // 死循环，永远跑下去 { if (RxFlag == 1) // ① 检查"信箱"里有没有新指令 { RxFlag = 0; // ② 先把标志清零（相当于"信件已读"） // ... 解析指令 ... RxLen = 0; // ③ 清空接收长度，准备收下一条指令 } } // RxFlag==0时，循环空转，什么都不做（继续等）
为什么用标志位而不是直接在中断里处理？因为中断要快进快出（在中断里做复杂操作会影响其他中断）。所以中断只做"收字符+置标志"这种轻量活，把"解析指令+执行操作"放到主循环里慢慢处理。这是嵌入式的经典设计模式。

③ 指令解析：用strcmp比对字符串

文件：user/main.c — 指令解析（节选）
if (strcmp((char*)RxBuf, "LED1_ON") == 0) { LED_Set(1); // 字符串匹配→点亮LED printf("[OK] LED 已点亮\r\n"); } else if (strcmp((char*)RxBuf, "BEEP_ON") == 0) { BEEP_Set(1); // 字符串匹配→开启蜂鸣器 printf("[OK] 蜂鸣器已开启\r\n"); } else { printf("[错误] 未知指令: %s\r\n", RxBuf); // 都不匹配→报错 }
通俗理解：strcmp就像"对暗号"。你说"LED1_ON"，它一个字符一个字符比对，完全一样就返回0（对上了），然后执行对应动作。对不上就试下一个暗号，都对不上就说"听不懂你在说啥"。

④ 串口接收中断（后台自动运行，你不用主动调用）

文件：hardwere/USART.c — 中断服务函数
void USART1_IRQHandler(void) { if (USART_GetITStatus(USART1, USART_IT_RXNE) == SET) { uint8_t ch = USART_ReceiveData(USART1); // ① 读走收到的字节 if (ch == '\n' || ch == '\r') // ② 遇到换行/回车→一条指令收完了 { RxBuf[RxLen] = '\0'; // 字符串末尾补0（C语言字符串约定） RxFlag = 1; // 置标志→通知主循环"有新指令" } else if (RxLen < 63) // ③ 普通字符→存入缓冲区 { RxBuf[RxLen++] = ch; } } }
关键细节：为什么遇到'\n'才认为一条指令结束？因为串口助手发送时，每行末尾会自动加换行符。我们用换行符作为"一条指令的结束标记"，这样就能区分"LED1_ON"和"LED1_OFF"是两条独立指令。RxLen<63是防越界保护，防止缓冲区溢出。

CHAPTER · V1

V1：ADC 数据采集（读电压和温度）

V1 目标功能：板子能自己测电压（电位器模拟）和温度（手捏NTC），通过串口打印出来，电压过高时LED亮报警。V0是"控制输出"，V1是"采集输入"——方向反过来了。

1. 先搞懂ADC是什么（最核心的概念）

通俗理解：单片机是数字世界的生物，它只认识0和1。但现实世界是模拟的——电压是连续变化的（3.15V、3.16V、3.157V……）。ADC（模数转换器）就是翻译官，把连续的模拟电压翻译成单片机能懂的数字。STM32F103的ADC是12位的，意思是它把0~3.3V分成了4096份（2^12=4096），每份约0.0008V。所以ADC读到的数字是0~4095，需要换算回电压。
图4：ADC 换算原理（模拟量 ↔ 数字量）
换算公式：电压 = ADC值 × 3.3 ÷ 4096。例如ADC读到3915，电压 = 3915 × 3.3 ÷ 4096 ≈ 3.157V。

2. 硬件连接（电压用分压，温度用NTC）

电压采集（PA0）

为什么要分压？车载电压可能到12V以上，但ADC只能测0~3.3V。所以用两个电阻把电压缩小一半（分压比2:1），12V变成6V……等等，6V还是超3.3V？

实际上V1阶段用的是电位器模拟，输出0~3.3V直接接PA0。代码里乘了2是为后续接真实车载电压预留的分压比。

温度采集（PA1）

NTC是什么？NTC是负温度系数热敏电阻——温度越高，电阻越小。把NTC和一个10K固定电阻串联，测中间点的电压，就能反推出NTC的阻值，再算出温度。

接线：3.3V → NTC → PA1 → 10K电阻 → GND

3. 温度怎么算出来的？（B值公式）

图5：NTC 测温推导流程
四步走：读ADC → 算电压 → 反推电阻 → B值公式算温度。NTC在25℃时阻值正好是10K，所以上面例子算出25℃。

4. 核心代码逐行拆解

① ADC初始化（ADC.c）

文件：hardwere/ADC.c — ADC1_Init
void ADC1_Init(void) { // ① 开时钟：ADC1和GPIOA都要开 RCC_APB2PeriphClockCmd(RCC_APB2Periph_ADC1 | RCC_APB2Periph_GPIOA, ENABLE); RCC_ADCCLKConfig(RCC_PCLK2_Div6); // ADC时钟=72M/6=12MHz（必须≤14MHz） // ② PA0、PA1配置为模拟输入（ADC引脚必须是模拟输入模式！） GPIO_InitStructure.GPIO_Pin = GPIO_Pin_0 | GPIO_Pin_1; GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AIN; GPIO_Init(GPIOA, &GPIO_InitStructure); // ③ 配置ADC：单次转换、右对齐、软件触发、独立模式 ADC_InitStructure.ADC_ContinuousConvMode = DISABLE; // 单次转换（读一次转一次） ADC_InitStructure.ADC_DataAlign = ADC_DataAlign_Right; // 右对齐（数值直接用） ADC_InitStructure.ADC_ExternalTrigConv = ADC_ExternalTrigConv_None; // 软件触发 ADC_InitStructure.ADC_Mode = ADC_Mode_Independent; // 独立模式 ADC_InitStructure.ADC_NbrOfChannel = 1; // 1个通道 ADC_InitStructure.ADC_ScanConvMode = DISABLE; // 非扫描 ADC_Init(ADC1, &ADC_InitStructure); // ④ 使能ADC + 校准（校准能提高精度，必须做！） ADC_Cmd(ADC1, ENABLE); ADC_ResetCalibration(ADC1); // 复位校准 while(ADC_GetResetCalibrationStatus(ADC1)); // 等复位完成 ADC_StartCalibration(ADC1); // 开始校准 while(ADC_GetCalibrationStatus(ADC1)); // 等校准完成 }
容易忘的两个点：① GPIO必须配成模拟输入（GPIO_Mode_AIN），配成其他模式ADC读不准；② 校准不能省，复位校准+开始校准两步都要等完成。这两个是新手最常踩的坑。

② 读一次ADC值（ADC.c）

文件：hardwere/ADC.c — ADC_GetValue
uint16_t ADC_GetValue(uint8_t channel) { // ① 每次读数前重新配置通道（这样PA0和PA1可以轮流读） ADC_RegularChannelConfig(ADC1, channel, 1, ADC_SampleTime_239Cycles5); // ② 软件触发，开始转换 ADC_SoftwareStartConvCmd(ADC1, ENABLE); // ③ 死等转换完成（EOC标志=End Of Conversion） while (ADC_GetFlagStatus(ADC1, ADC_FLAG_EOC) == RESET); // ④ 读结果（0~4095） return ADC_GetConversionValue(ADC1); }

③ 多次采样取平均（软件滤波）

文件：hardwere/ADC.c — Sample_Avg
float Sample_Avg(uint8_t channel) { uint32_t sum = 0; for (uint8_t i = 0; i < 10; i++) // 连续读10次 { sum += ADC_GetValue(channel); } return sum / 10.0f; // 取平均，减小随机噪声 }
为什么要取平均？ADC读数会有随机噪声（比如电源波动、电磁干扰），单次读数可能跳来跳去。连续读10次取平均，就像你量身高量了10次取平均值，结果更稳定。这是最简单的软件滤波方法。

④ main.c主循环（V1版本）

文件：user/main.c — V1主循环（对比V0，只多了ADC相关代码）
#include "ADC.h" // 新增：包含ADC头文件 int main(void) { LED_Init(); BEEP_Init(); USART1_Init(115200); ADC1_Init(); // 新增：ADC初始化 while(1) { float volt = Sample_Avg(ADC_Channel_0) * 3.3f / 4096.0f * 2.0f; // 读PA0，10次平均 → 换算电压（×分压比2） float temp = NTC_GetTemp(); // 读PA1，NTC换算温度 printf("电压: %.2fV | 温度: %.1f℃\r\n", volt, temp); if(volt > 14.0f) { // 超压报警 GPIO_ResetBits(GPIOA, GPIO_Pin_8); // LED亮 printf("[警告] 电压过高!\r\n"); } else { GPIO_SetBits(GPIOA, GPIO_Pin_8); // LED灭 } Delay_ms(500); // 500ms采一次 } }
看出来了吗？V1和V0的main.c结构几乎一样！只是多了3行：包含ADC.h、调用ADC1_Init()、主循环里读电压温度。这就是"版本叠加"的好处——地基打好了，加新功能只是加几行代码。

CHAPTER · V2

V2：OLED 显示（数据上屏，脱离电脑独立工作）

V2 目标功能：电压和温度不再只靠串口打印，而是直接显示在OLED屏幕上。从此板子不用连电脑也能看到数据。核心难点不是"显示"，而是"怎么显示不闪烁"——局部刷新技巧是本章精髓。

1. OLED是什么？I2C又是什么？

OLED屏幕

我们用的是0.96寸OLED，分辨率128×64像素，内部控制器是SSD1306。它通过I2C接口和单片机通信，I2C地址固定是0x78。

屏幕本身不认识字符，只认识"哪些像素点亮"。所以需要字库。

I2C总线

I2C只需要两根线：SCL（时钟线）和SDA（数据线）。所有设备挂在这两根线上，靠地址区分。我们用软件模拟I2C时序（GPIO翻转），引脚随便选。

PB8=SCL, PB9=SDA，必须配开漏输出。

2. I2C通信时序（4个基本动作）

图6：I2C 起始/停止/写字节 时序图
起始START：SCL高电平时，SDA从高变低（图中最左边SDA先掉下去） ② 写字节：SCL低电平时改变SDA，SCL高电平时从机读取（8位，高位先发） ③ 应答ACK：第9个时钟，从机拉低SDA表示"收到了"；④ 停止STOP：SCL高时SDA从低变高
软件I2C就是用GPIO翻转模拟这个时序。你在代码里看到的I2C_Start/I2C_Stop/I2C_SendByte，就是在严格按照这个时序拉高拉低引脚。

3. OLED显示原理（字库+显存）

通俗理解：OLED屏幕就像一个128×64的围棋盘，每个交叉点是一个像素（能亮能灭）。SSD1306把这个棋盘分成8"页"（Page0~7），每页8行高、128列宽。你告诉它"第3页第10列写0b10101010"，它就把那一列的8个像素按这个字节亮灭。显示字符就是把字符的点阵数据一列一列写进去。
图7：OLED 页地址模式 + 字符显示原理（以字母'A'为例）
OLED_ShowChar做的事：先设光标到上半页，写8字节（上半部分），再设光标到下半页，写8字节（下半部分）。一个字符就显示出来了。

4. 本章精髓：局部刷新（为什么不闪烁）

新手最常见的错误：每次循环都 OLED_Clear() 清屏，然后重绘全部内容。结果就是屏幕疯狂闪烁——因为清屏和重绘之间有短暂的"全黑"时间，人眼能察觉到。
图8：错误做法 vs 正确做法
核心思想：不变的东西只写一次，变的东西只覆盖变化的区域。"Volt:"这个标签500年不变，为什么要每次重绘？只把数字那几列覆盖掉就行。

5. 核心代码逐行拆解

① main.c初始化（标签只写一次）

文件：user/main.c — V2初始化段
OLED_Init(); // 初始化OLED（内部会先初始化软件I2C） // ===== 静态标签只写一次（局部刷新核心）===== OLED_ShowString(1, 1, "Volt:"); // 第1行第1列：电压标签 OLED_ShowString(2, 1, "Temp:"); // 第2行第1列：温度标签 OLED_ShowString(3, 1, "Status:"); // 第3行第1列：状态标签 OLED_ShowString(4, 1, "CarGuard V2"); // 第4行：版本信息
坐标怎么看？OLED_ShowString(Line, Column, ...) 中 Line=1~4（每行16像素高），Column=1~16（每列8像素宽）。一个字符占1列。所以"Volt:"占5列（V-o-l-t-:），数字从第6列开始写。

② main.c主循环（只更新数字区域）

文件：user/main.c — V2主循环显示部分
while(1) { float volt = Sample_Avg(ADC_Channel_0) * 3.3f / 4096.0f * 2.0f; float temp = NTC_GetTemp(); // 电压：第1行第6列起，2位整数+2位小数（含符号共6列） OLED_ShowFloatNum(1, 6, volt, 2, 2); OLED_ShowChar(1, 12, 'V'); // 单位V在第12列 // 温度：第2行第6列起，2位整数+1位小数（含符号共5列） OLED_ShowFloatNum(2, 6, temp, 2, 1); OLED_ShowChar(2, 11, 'C'); // 单位C在第11列 // 状态：只更新第3行第8列起的6个字符 if(volt > 14.0f) { OLED_ShowString(3, 8, "Warn!!"); } else { OLED_ShowString(3, 8, "Normal"); } Delay_ms(500); }
就像填表：表格的表头（"Volt:""Temp:"）打印一次就不动了，每次只需要把数字栏里的旧数字用新数字覆盖掉。你不会每次填表都把整张表重新画一遍吧？OLED局部刷新就是这个道理。

③ 浮点数显示函数（OLED.c，V2新增）

文件：hardwere/OLED.c — OLED_ShowFloatNum（核心逻辑）
void OLED_ShowFloatNum(uint8_t Line, uint8_t Column, float Number, uint8_t IntLen, uint8_t DecLen) { // ① 符号位：负数显示'-'，正数显示空格（保持对齐） if (Number < 0) { OLED_ShowChar(Line, col, '-'); Number = -Number; } else { OLED_ShowChar(Line, col, ' '); } // ② 把浮点数放大成整数（如12.34×100=1234），+0.5实现四舍五入 uint32_t scaled = (uint32_t)(Number * scale + 0.5f); // ③ 分离整数部分和小数部分 intPart = scaled / (uint32_t)scale; // 1234/100 = 12 decPart = scaled % (uint32_t)scale; // 1234%100 = 34 // ④ 依次显示：整数部分 → 小数点 → 小数部分 OLED_ShowNum(Line, col, intPart, IntLen); OLED_ShowChar(Line, col+IntLen, '.'); OLED_ShowNum(Line, col+IntLen+1, decPart, DecLen); }
为什么不直接用printf打印到OLED？因为printf是输出到串口的，OLED没有"标准输出"的概念。而且OLED需要精确定位到某行某列，printf做不到。所以我们自己写浮点数显示函数——思路就是"放大成整数→拆分→逐位显示"。

METHODOLOGY

怎么练到"自己能写出来"？

1. 写任何外设驱动的万能四步法

  1. 开时钟——外设和对应的GPIO都要开时钟（RCC_APB2PeriphClockCmd）。忘了开时钟，后面配置全无效。
  2. 配GPIO——输入还是输出？推挽还是开漏？上拉还是浮空？根据外设需求选对模式。（ADC要模拟输入、I2C要开漏、LED要推挽输出、按键要上拉输入）
  3. 配外设——填初始化结构体（USART_InitTypeDef / ADC_InitTypeDef），调用Init函数，使能外设。
  4. 写读写函数——封装"发一个字节""读一个值"这种最底层操作，再在上面组合出高级功能。

2. main.c的万能结构

int main(void) { // ===== 第一部分：初始化（只执行一次）===== // 按顺序初始化每个外设：LED → BEEP → 串口 → ADC → OLED // 每个外设一行Init调用 // ===== 第二部分：一次性设置（如OLED静态标签）===== // 不变的东西在这里写一次 // ===== 第三部分：主循环（反复执行）===== while(1) { // ① 采集输入（读ADC/按键等） // ② 处理数据（换算/判断/滤波） // ③ 输出结果（串口打印/OLED显示/LED报警） // ④ 延时或等待（控制刷新频率） } }

3. 自测清单（写完代码后对照检查）

编译前检查
  • 每个.c文件都#include了对应的.h
  • 函数名在.h声明、.c定义、调用处三处一致
  • 没有和标准库重名（如I2C_Init→改I2C1_Init）
  • Keil工程里添加了所有.c文件
硬件检查
  • 引脚有没有冲突（两个外设不能共用一个引脚）
  • GPIO模式对不对（ADC要AIN、I2C要OD）
  • 接线对不对（串口TX交叉接、I2C地址对不对）
  • 供电够不够（OLED要3.3V不要接5V）
逻辑检查
  • 初始化顺序对不对（被依赖的先初始化）
  • 有没有忘记校准（ADC必须校准）
  • 显示有没有闪烁（是不是每次都Clear了）
  • 数值对不对（串口和OLED数值是否一致）

4. 学习建议（从"看懂"到"会写"）

第一遍：照着教程抄一遍，能编译通过、能跑起来就行。不追求理解每一行。
第二遍：关掉教程，凭记忆重写，写不出来的地方看一眼提示。重点理解"为什么这么写"。
第三遍：换个引脚、换个外设（比如把LED从PA8改到PB5），自己修改代码验证。能独立改成功，说明真的懂了。
终极检验：拿一个全新的外设（比如DHT11温湿度传感器），只看数据手册，自己写出驱动。能写出来，你就出师了。
记住：嵌入式开发没有魔法，所有复杂的功能都是"初始化→读→处理→写"这四步的组合。把每个外设的"四步法"练熟，把main.c的"三段式"结构刻进脑子里，V3、V4、V5……不过是在这个骨架上继续加外设而已。
